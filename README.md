# 叠到第几层

面向存内计算的 **3D 异构集成架构** 与 **供电—热协同优化（STCO）**。

作品面向 *第四届全国先进计算技术创新大赛 · 技术突破赛道 · 「面向存内计算的3D异构集成架构设计与供电—热系统协同优化」*
（主办：中国信息通信研究院；出题：杭州微纳核芯电子科技）。

一句话：**在 24 mm² 的足迹上装 7B@4bit，最多能叠几层；从第几层开始，叠上去是白叠的。**

## 结论（全部由 `out/results.json` 复算）

| 问题 | 答案 |
|---|---|
| 装下 7B@4bit 要几层 | **3 层**（单层 1200 MB，模型 3338 MB） |
| 2 层会怎样 | 风冷 **177 tok/s**；3 层一步到 **10,133 tok/s**（57 倍，悬崖不是斜坡） |
| 风冷多叠几层 | 没用：3 层 10,133 → 8 层 10,116（差 0.2%）；足迹热流密度锁在 0.5 W/mm² |
| 冷板多叠几层 | 到第 4 层为止（55,820，+24%）；第 5 层起 55,744 不再涨 |
| 供电是不是墙 | IR 只有 34.3 mV（预算 37.5）；真约束是**单根 TSV 载流** → 需 ≥43 个/mm² |
| 层序要紧吗 | 不要紧：最优与最差差 1.1 K（薄 die 的层间热阻只有外部热阻的 2%） |

**核心恒等式**（忽略泄漏与静态功耗）：`tok/s ≤ (q_max · A − P_static) / E_token`。
这个式子里没有 N——**层数只决定「装不装得下」和「够不够到这条线」，不决定线有多高。**

## 跑法

```bash
py -3 run.py          # 模型 → out/results.json → 图 → 方案书 PDF → 作品页
py -3 verify.py       # 190 条断言，全过 EXIT=0
```

只依赖 `numpy`；出图用 `matplotlib`；PDF 由 Chromium 打印 HTML 生成（`stco/deck.py` 里自动找浏览器）。
`site/index.html` 是与 PDF 同源的网页版（图片走相对路径）。

## 目录

```
stco/params.py     参数单一来源：每个值带 unit / kind(pub|est|derived) / 区间
stco/thermal.py    一维热阻网络（G·T=P）、泄漏—温度不动点、层序穷举
stco/design.py     单设计评估：容量 → 能量 → 两工况功耗 → 温度 → 供电
stco/explore.py    8 层 × 2 冷却 × 单/双面扫掠、容量计划、敏感度、供电预算
stco/figures.py    六张图（全部读 results.json，不手写数字）
stco/deck.py       14 页方案书（HTML → PDF）与作品页
verify.py          190 条断言：参数/容量/能量/热/吞吐/供电/产物与确定性
docs/              四道闸的记录与教训
```

## 两条必须分清的口径

- **解码（decode）**：吞吐低，功耗 ∝ 吞吐，决定**容量**够不够；
- **满速（prefill / 大 batch）**：阵列满频，功耗与吞吐无关，决定**散热与供电**。

把两者混在一起，会得出「CIM 很省电所以不热」或「堆得越高算力越强」两种错结论。

## 边界

解析模型 + 数值求解，**不是硅测量**：没有流片、没有版图、没有 PPA 签核。
不含成品率、TSV 应力、电迁移寿命、封装翘曲与软件栈效率。
最弱的假设是面密度 ρ（50 MB/mm²）与面热流上限 q_max（0.5 / 2.0 W/mm²），两者都在第 12 页做了敏感度。
