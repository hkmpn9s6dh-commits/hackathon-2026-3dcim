# 闸 B：模型 + 断言

## 做了什么

四本账（容量 / 能量 / 热 / 供电）写成同一个变量 N 的函数，一次跑完 8 层 × 2 冷却 × 单/双面 = 32 个设计点，
再叠上容量计划（5 个模型）、层序穷举（20 种去重排列）、6 参数敏感度、供电预算扫描。

## 关键实现决定

1. **所有能量都必须落到某一层上**。第一版把「搬运权重」的能量只算进总功耗、没进热网络，结果得出
   "2 层也能跑 900 tok/s"——自相矛盾。改成搬运能量落在逻辑层的存储接口上，容量不够立刻在温度上显形。
2. **面热流密度上限 q_max 必须显式建模**。只给 R_hs 的话，模型会允许 24 mm² 里塞 624 W
   （冷板 0.08 K/W × 50 K）。加了 q_max（风冷 0.5、冷板 2.0 W/mm²）之后，"墙"才落到正确的轴上。
3. **两个工况分开算**：decode 决定容量，满速决定散热与供电。
4. **单层解析对齐**：一维网络在 n=1、无泄漏时与 `T = T_amb + P·(R_hs + R_TIM/A + R_if/A)` 逐位一致。

## 断言

`py -3 verify.py` → **PASS 190 / 190，EXIT=0**。分组：

- 参数：字段齐、kind 合法、区间自洽（约 100 条）
- 容量：公式、向上取整、3 层装得下 / 2 层装不下、参数单调
- 能量：算力地板、三种策略的加减关系、搬运比值只由每 bit 能量决定
- 热：单层解析对齐、零功率回环境温度、G 对称、内部节点热流守恒、不动点稳定、无泄漏时线性、
  泄漏每 20 K 翻倍、85 °C 处 64%
- 吞吐：不超过算力上限、不超过热流预算、约束标签合法、容量悬崖 >10 倍、4→8 层平台 <1%、
  峰值不超过 4 层、设计点算力受限
- 供电：I=P/V、TSV 计数、单根电流、IR 两项相加、IR 判定与阈值一致、所需密度公式、默认密度不够
- 产物与确定性：两次 build_results 逐字节一致、无 NaN、磁盘 JSON 与现算一致、
  PDF 14 页且含关键数字、"不是硅测量"声明、六张图、作品页

## 修掉的三个真 bug（都是断言抓到的）

1. **功率落在散热器节点上**：`rhs[:n] = p` 应为 `rhs[1:n+1] = p`，导致单层解恒等于 `T_amb + P·R_hs`。
   解析对齐这条断言直接抓住了它。
2. **占空比乘了两次 N**：`duty = min(1, s/ceiling)·N` 让 4 层比 3 层吞吐更低（13,994 vs 44,939）。
   平台检验断言抓的。
3. **双面冷却没有第二份热流预算**：双面风冷与单面完全一样，等于把双面做成了摆设。
